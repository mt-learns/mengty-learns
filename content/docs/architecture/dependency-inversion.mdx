<Intent>
The **Dependency Inversion Principle (DIP)** is the mechanism behind Hexagonal, Onion, and Clean architectures: high-level business rules (`PlaceOrderService`) do not import low-level drivers (`PostgresOrderRepo`). Instead, **both depend on an abstraction** (`OrderRepository`) owned by the business layer.
</Intent>

## The Problem: Concrete Imports Lock You In

In a standard layered setup, `PlaceOrderService` directly imports `PostgresOrderRepo`. Even if you pass it via constructor injection, the `import` statement at the top of the file still creates a compile-time dependency on Postgres, its types, and its error classes.

## The Solution: Invert the Arrow Across the Boundary

Move the `OrderRepository` interface **into the domain/business module**, and make `PostgresOrderRepo` implement it from the infrastructure module. Source code imports now point **from infrastructure toward the domain**, while runtime control still flows from domain to Postgres.

## Code: Before vs After DIP

<Tabs items={['TypeScript (After DIP)', 'TypeScript (Before DIP)']}>
  <Tab value="TypeScript (After DIP)">
```ts
// --- domain/order.ts (owns the abstraction) ---
export interface Order {
  id: string;
  totalCents: number;
}

export interface OrderRepository {
  save(order: Order): Promise<void>;
}

export class PlaceOrderService {
  constructor(private readonly repo: OrderRepository) {}

  async execute(totalCents: number): Promise<Order> {
    const order = { id: crypto.randomUUID(), totalCents };
    await this.repo.save(order);
    return order;
  }
}

// --- infra/postgres-order-repo.ts (depends on domain/) ---
export class PostgresOrderRepo implements OrderRepository {
  async save(order: Order): Promise<void> {
    // INSERT INTO orders ...
    void order;
  }
}
```
  </Tab>
  <Tab value="TypeScript (Before DIP)">
```ts
// --- business/place-order-service.ts ---
import { PostgresOrderRepo } from '../infra/postgres-order-repo';

export class PlaceOrderService {
  private readonly repo = new PostgresOrderRepo(); // coupled to SQL driver

  async execute(totalCents: number) {
    return this.repo.insert(totalCents);
  }
}
```
  </Tab>
</Tabs>

## How DIP Relates to the Bridge Pattern

Notice how identical this structure is to the [Bridge Pattern](/docs/design/bridge):

- **Bridge** separates an Abstraction hierarchy (`RemoteControl`) from an Implementation hierarchy (`Device` interface → `TV`, `Radio`) using composition.
- **Dependency Inversion** applies that same composition-over-interface idea at **architectural module boundaries** (`PlaceOrderService` → `OrderRepository` ← `PostgresOrderRepo`).

<MyTake>
The most common mistake with Dependency Inversion is putting the `OrderRepository` interface in the `infra/` folder. If `domain/` imports an interface from `infra/`, you have not inverted anything—the domain still depends on infrastructure. Always place the interface in the module that **calls** it.
</MyTake>
