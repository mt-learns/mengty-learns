## TL;DR
**Normalize (3NF) your write model** so every fact has one source of truth, and **denormalize only on separate read paths** (materialized views or CQRS projections) when heavy aggregations threaten OLTP latency. Never duplicate mutable totals across operational tables in app code.

## Why it exists
Running a 9-table, 50-million-row analytics query on your primary OLTP database flushes the buffer cache and holds long transactions that block `autovacuum`. Conversely, flattening `customer_name` or `order_total` onto multiple operational tables in application code almost always causes silent drift when one write path forgets to update the copy.

**Write truth once; project read shapes separately.**

## Do it

### Decision matrix

| Situation | Use 3NF + Indexes | Use Materialized View / Read Model |
|---|---|---|
| Single-record lookup joining 4 indexed tables | **Yes** (fast index lookups) | No |
| Dashboard aggregating 20M rows every 5 minutes | No | **Yes** (precomputed, bounded staleness) |
| Regulatory / financial write path | **Yes** (auditable, zero drift) | No |
| Cross-service summary view | No | **Yes** (async projection) |

### Safe materialized view refresh in PostgreSQL

```sql
CREATE MATERIALIZED VIEW monthly_order_summary AS
SELECT date_trunc('month', created_at) AS month,
       merchant_id,
       COUNT(*) AS order_count,
       SUM(total_cents) AS gross_cents
FROM orders
GROUP BY 1, 2;

-- Required so REFRESH ... CONCURRENTLY does not block readers
CREATE UNIQUE INDEX idx_monthly_order_summary_pk
  ON monthly_order_summary (month, merchant_id);

REFRESH MATERIALIZED VIEW CONCURRENTLY monthly_order_summary;
```

## Gotchas
- **Denormalizing to "avoid joins":** Indexed foreign-key joins for a single entity take sub-millisecond time; denormalizing them trades correctness for zero real gain.
- **Missing `CONCURRENTLY`:** Plain `REFRESH MATERIALIZED VIEW` takes an `AccessExclusiveLock` and blocks all readers until the refresh finishes.
- **Silent staleness:** Always expose `refreshed_at` in dashboard responses so users know how fresh the read model is.

## Production checklist
- [ ] Keep transactional tables in 3NF with foreign keys and proper indexes.
- [ ] Cap read-only reporting query timeouts (e.g. `statement_timeout = '5s'`) so reports cannot stall `autovacuum`.
- [ ] Add a `UNIQUE` index on materialized views and refresh with `CONCURRENTLY`.
- [ ] If you ever denormalize a column on a write table, enforce it via a database trigger/generated column + reconciliation check—not app code alone.
