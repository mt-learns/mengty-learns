## TL;DR
Use **gRPC + Protobuf** for latency-sensitive, internal service-to-service calls where compiled contracts eliminate DTO drift and HTTP/2 multiplexing + binary framing cut serialization overhead. Keep **field numbers permanent** (`reserved` when retired), propagate **deadlines**, and put a **REST/BFF gateway** at the browser/partner edge.

## Why it exists
When internal microservices pass JSON over HTTP/1.1, a renamed field in Service A can silently deserialize as `undefined` or `0` in Service B—passing unit tests on both sides while corrupting production data. Compiling `.proto` schemas turns contract drift into a build-time error.

## Mental model
Protobuf sends **field numbers**, not field names, over HTTP/2—and `buf breaking` in CI guards wire compatibility.

## Do it

### Wire-compatibility rules in `.proto`

```protobuf
syntax = "proto3";
package orders.v1;

message SubmitOrderRequest {
  reserved 3;                 // Retired tag number: never reuse!
  reserved "legacy_code";     // Retired field name

  string order_id = 1;        // Tags 1..15 use 1 byte on the wire
  int64 amount_cents = 2;
  OrderChannel channel = 4;
}

enum OrderChannel {
  ORDER_CHANNEL_UNSPECIFIED = 0; // Always reserve 0 for unknown/default
  ORDER_CHANNEL_WEB = 1;
  ORDER_CHANNEL_API = 2;
}
```

### Key rules for safe evolution
- **Never change a field number** or reuse a retired number (`reserved` enforces this).
- **Never change a field's type** or switch between `singular` and `repeated`.
- **Always define `_UNSPECIFIED = 0`** on every enum so unknown values from newer peers are handled explicitly.
- **Retry only `UNAVAILABLE` / `RESOURCE_EXHAUSTED`**, never `DEADLINE_EXCEEDED` (the budget is already spent).

## Gotchas
- **HTTP/1.1 L4 load balancing:** A single long-lived HTTP/2 TCP connection pins all gRPC RPCs to one pod unless you use L7-aware load balancing (Envoy/mesh/client-side round-robin).
- **Debugging opaque payloads:** Binary frames aren't human-readable in `tcpdump` or `curl`—use `grpcurl` with server reflection (in non-prod) and OpenTelemetry tracing.
- **Missing deadlines:** Calling gRPC without a deadline defaults to waiting indefinitely on a hung server.

## Production checklist
- [ ] Run `buf lint` and `buf breaking` in CI on every `.proto` change.
- [ ] Set explicit deadlines on every gRPC call and propagate incoming deadlines downstream.
- [ ] Use L7 load balancing (or client-side `round_robin`) over HTTP/2 connections.
- [ ] Enforce mTLS between internal gRPC workloads.
