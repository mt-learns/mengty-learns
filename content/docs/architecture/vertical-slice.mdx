## TL;DR
**Vertical Slice Architecture** organizes code **by feature** (`features/place-order/`, `features/cancel-order/`) rather than horizontal layers (`controllers/`, `services/`, `repos/`). Each slice owns its request, logic, and query end-to-end, so changing one feature doesn't ripple through shared layers.

## Intent
<Intent>
Maximize cohesion along the axis of change—when a product feature changes, you open one folder and edit one slice instead of touching five horizontal layers.
</Intent>

## Problem
In a traditional Layered Architecture, adding one field to `PlaceOrder` forces edits across `OrderController`, `OrderService`, `OrderMapper`, `OrderRepository`, and shared `OrderDto`s used by 12 other endpoints. Shared "Service" classes grow to thousands of lines, and every feature pays the abstraction tax of the most complex feature.

## Solution
Flip the axis from **horizontal layers** to **vertical slices**:

- Each use case (`PlaceOrder`, `GetOrderHistory`, `CancelOrder`) is a self-contained slice with its own input schema, handler, and persistence call.
- **Simple slices stay simple:** `GetOrderHistory` can run a direct SQL query and return a flat DTO—no repository interface or domain entity needed.
- **Complex slices stay rich:** `PlaceOrder` can invoke a tactical DDD `Order` aggregate if it has complex pricing/inventory invariants.

## Real-world analogy
<Analogy>
Think of a **food court** vs a **single giant assembly line**. In a food court, the taco stall (`PlaceOrder`) and the coffee stall (`GetOrder`) each have their own counter, prep area, and register—changing the taco menu never slows down coffee orders.
</Analogy>

## Code
A self-contained `place-order` slice in TypeScript:

```ts
// src/features/place-order/handler.ts
export interface PlaceOrderInput {
  customerId: string;
  items: Array<{ sku: string; priceCents: number; qty: number }>;
}

export async function handlePlaceOrder(
  input: PlaceOrderInput,
  saveOrder: (row: { id: string; totalCents: number }) => Promise<void>,
) {
  if (input.items.length === 0) throw new Error('Empty order');
  const totalCents = input.items.reduce((s, i) => s + i.priceCents * i.qty, 0);
  const id = crypto.randomUUID();
  await saveOrder({ id, totalCents });
  return { orderId: id, totalCents };
}
```

## When to use / when to avoid

    'Core domain logic shared across 10+ endpoints—extract shared Aggregates/Value Objects rather than copy-pasting rules.',
  ]}

## How to implement
<Steps>
  <Step>
    ### Group by feature folder
    Create `src/features/<use-case>/` containing `handler.ts`, `schema.ts`, and `handler.test.ts`.
  </Step>
  <Step>
    ### Keep slices independent
    Never import `features/a/handler` from `features/b/handler`; extract shared domain rules to `src/domain/` only when truly shared.
  </Step>
</Steps>

## Pros / Cons
<ProsCons
  pros={[
