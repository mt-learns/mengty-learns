## TL;DR
The **Proxy** pattern wraps a service behind the **same interface** to control access—handling authorization, caching, lazy loading, or audit logging before forwarding allowed calls to the real object.

## 1. Intent

<Intent>
Provide a surrogate or placeholder for another object to control access to it, without changing the interface clients use.
</Intent>

## 2. Problem

Suppose your platform CLI talks to a `ClusterSecretsClient` that reads and rotates Kubernetes secrets. Now you need two cross-cutting controls:
1. Only operators with the `secrets:read` role may fetch values, and every access must be audited.
2. Repeated reads of unchanged config secrets within 30 seconds should hit an in-memory cache instead of hammering the API server.

If you embed RBAC checks, audit logs, and TTL caching directly inside `ClusterSecretsClient`, the core client mixes infrastructure concerns with secret-fetching logic—and every other client class ends up duplicating the same boilerplate.

## 3. Solution

Define a shared `SecretsReader` interface implemented by both `RealSecretsClient` and `ProtectedSecretsProxy`.

The proxy holds a reference to `RealSecretsClient`. When a caller invokes `getSecret(key, actor)`:
- If `actor` lacks permission, the proxy throws `ForbiddenError` immediately—the real client is never called.
- If the key is cached and fresh, the proxy returns the cached value.
- Otherwise, the proxy forwards the call to `RealSecretsClient`, records an audit entry, caches the result, and returns it.

## 4. Real-world analogy

<Analogy>
Think of a **reverse proxy** (like Nginx or Envoy) sitting in front of an internal microservice. Downstream callers speak the exact same HTTP contract, while the reverse proxy terminates TLS, enforces rate limits, checks JWT scopes, and caches `GET` responses before forwarding valid traffic to the upstream app.
</Analogy>

## 7. Code

```ts
export interface Actor {
  id: string;
  roles: readonly string[];
}

export interface SecretsReader {
  getSecret(key: string, actor: Actor): Promise<string>;
}

export class RealSecretsClient implements SecretsReader {
  async getSecret(key: string): Promise<string> {
    // Real implementation would call Vault or Kubernetes API
    return `secret-value-for-${key}`;
  }
}

export class ProtectedCachedSecretsProxy implements SecretsReader {
  private cache = new Map<string, { value: string; expiresAt: number }>();

  constructor(
    private readonly target: SecretsReader,
    private readonly ttlMs = 30_000,
    private readonly audit: (msg: string) => void = console.log,
  ) {}

  async getSecret(key: string, actor: Actor): Promise<string> {
    if (!actor.roles.includes('secrets:read')) {
      this.audit(`DENY actor=${actor.id} key=${key}`);
      throw new Error(`Forbidden: ${actor.id} lacks secrets:read`);
    }

    const hit = this.cache.get(key);
    if (hit && hit.expiresAt > Date.now()) {
      this.audit(`CACHE_HIT actor=${actor.id} key=${key}`);
      return hit.value;
    }

    const value = await this.target.getSecret(key, actor);
    this.cache.set(key, { value, expiresAt: Date.now() + this.ttlMs });
    this.audit(`ALLOW_FETCH actor=${actor.id} key=${key}`);
    return value;
  }
}
```

## 8. When to use / when to avoid

<Checklist
  use={[
    "Protection proxy: enforce authorization or rate limits before an expensive or sensitive service runs.",
    "Caching / Virtual proxy: defer heavy initialization or memoize read-only responses transparently.",
    "Audit / Remote proxy: log calls or wrap an RPC stub behind a local interface.",
  ]}
  avoid={[
    "Do not put core business rules inside a proxy—keep them in the real service.",
    "If you need to change the method signatures, use Adapter instead of Proxy.",
    "In JavaScript/TypeScript, avoid the built-in global Proxy object for simple wrapper classes unless you genuinely need dynamic property interception.",
  ]}
/>

## 9. How to implement

<Steps>
  <Step>
    ### Extract a shared interface
    Define an interface (`SecretsReader`) implemented by both the real service and the proxy.
  </Step>
  <Step>
    ### Inject the real service into the proxy
    Have the proxy accept the real service in its constructor and store it as a field.
  </Step>
  <Step>
    ### Add control logic around delegation
    Implement authorization checks, cache lookups, lazy init, or audit logging before/after forwarding.
  </Step>
  <Step>
    ### Wire at the composition root
    Pass the proxy to callers instead of the raw service.
  </Step>
  <Step>
    ### Test allowed and denied paths
    Verify unauthorized calls fail at the proxy without invoking the real service.
  </Step>
</Steps>
