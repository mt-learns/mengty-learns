## TL;DR
The classic **Singleton** (`ClassName.getInstance()`) hides dependencies, leaks global mutable state across tests, and violates Single Responsibility. Instead of hand-rolling `getInstance()`, create one instance at your **composition root** and pass it via **dependency injection**.

## Why it exists
Sometimes a system genuinely needs a single shared resource—such as a PostgreSQL connection pool, a telemetry exporter, or immutable startup config. The GoF Singleton solved this in 1994 by locking the constructor and exposing a static `getInstance()` method, before dependency injection containers and ES modules were standard.

## Mental model
Separate **lifetime** (how many instances exist) from **access** (how callers receive it).

## Do it

### Replace `getInstance()` with constructor injection

```ts
// Avoid: hidden global dependency + impossible to swap in tests
class ConfigRegistry {
  private static instance: ConfigRegistry;
  private constructor(public readonly region: string) {}
  static getInstance(): ConfigRegistry {
    if (!ConfigRegistry.instance) {
      ConfigRegistry.instance = new ConfigRegistry(process.env.REGION ?? 'us-east-1');
    }
    return ConfigRegistry.instance;
  }
}

// Prefer: plain class instantiated once at startup and passed explicitly
export interface AppConfig {
  readonly region: string;
}

export class DeployService {
  constructor(private readonly config: AppConfig) {}
  targetRegion() {
    return this.config.region;
  }
}

// Composition root (main.ts): single shared instance
const config: AppConfig = Object.freeze({ region: process.env.REGION ?? 'us-east-1' });
const deployService = new DeployService(config);
```

### When a single instance IS fine
- **DI-managed singleton scope:** Frameworks like NestJS or Spring manage one bean per container by default while still injecting it through constructors.
- **Frozen constants / stateless helpers:** Immutable values (`Object.freeze(...)`) or pure functions have no mutable state to corrupt tests.

## Gotchas
- **Test pollution:** A mutable Singleton cache or counter populated in Test A silently breaks Test B when tests run in the same process.
- **Hidden coupling:** Functions with zero parameters that secretly call `MetricsSingleton.getInstance()` lie about their dependencies.
- **Module-cache assumptions in Serverless / Edge:** In Next.js or serverless workers, module-level singletons live per isolate, not globally across all replicas.

## Production checklist
- [ ] Never write `private constructor()` + `static getInstance()` for business services.
- [ ] Create shared pools/clients once in `main.ts` (or a DI container) and pass them via constructor parameters.
- [ ] Freeze any module-level config object (`Object.freeze`) so tests cannot mutate it.
