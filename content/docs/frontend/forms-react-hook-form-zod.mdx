## TL;DR

- **One schema, two executions:** the same Zod schema runs in the browser for feedback and in the Server Action for truth. The client copy is a UX feature; the server copy is the control.
- **React Hook Form** keeps field state in refs and re-renders narrowly, so a 60-field application stays responsive; `zodResolver` connects the schema to the form.
- **Errors are a data contract:** `superRefine` for cross-field rules, dotted paths from the server, `setError` + focus on the first invalid field, and a live region for screen readers.

## Why it exists

A validation rule written twice is a rule that will disagree with itself. One team writes the React `onChange` check from a requirements document; another team writes the Bean Validation annotation three months later. Then the company registration regex differs by one character, the per-field percentage check never sees the total, and the trading-address schema forgot the postcode. Users fill nine steps, upload documents, and get a terminal error on submit with no field mapping. The fix is not more checks; it is deleting both rule sets and replacing them with one schema that the form and the server both import.

## Mental model

**One schema, two executions.** Client execution is fast, per-field feedback. Server execution is the decision, and it runs even when the request did not come from your form. Sharing the schema is what makes the two agree.

**React Hook Form's model.** Input state lives in refs and subscriptions are narrow, so typing in field 40 does not re-render fields 1-39. The pieces you use:

| API | Role |
|---|---|
| `useForm({ resolver: zodResolver(schema), defaultValues })` | Typed form instance; defaults start inference |
| `register` / `Controller` | Native inputs vs. controlled third-party widgets |
| `useFieldArray` | Repeating sections: owners, directors, line items |
| `formState` | `errors`, `isSubmitting`, `isDirty`, `isValid` |
| `setError` | The channel for mapping server errors back to fields |
| `mode: 'onBlur'` | Validate when the user leaves the field, not on every keystroke |

**Slices, not forks.** A multi-step wizard uses `schema.pick({ ... })` per step. It is still the same schema, so the step rules cannot drift. Object-level `superRefine` does not run on a slice, so cross-field rules are re-run whole on the server.

## Do it

Define the rules once, with messages that say what to do:

```ts
import { z } from 'zod'

const address = z.object({
  line1: z.string().trim().min(1, 'Enter the first line of the address'),
  city: z.string().trim().min(1, 'Enter a town or city'),
  postcode: z.string().trim().regex(/^[A-Z]{1,2}\d[A-Z\d]?\s?\d[A-Z]{2}$/i, 'Enter a valid postcode'),
})

export const applicationSchema = z
  .object({
    legalName: z.string().trim().min(2, 'Enter the registered legal name'),
    registrationNumber: z
      .string()
      .trim()
      .toUpperCase()
      .regex(/^(?:\d{8}|[A-Z]{2}\d{6})$/, 'Enter 8 digits, or 2 letters followed by 6 digits'),
    registeredAddress: address,
    tradingAddress: address,
    owners: z
      .array(
        z.object({
          name: z.string().trim().min(2, 'Enter the owner name'),
          percent: z.coerce.number().min(25.01, 'Only owners above 25% must be declared').max(100),
        }),
      )
      .min(1, 'Declare at least one owner above 25%'),
  })
  .superRefine((data, ctx) => {
    const total = data.owners.reduce((sum, owner) => sum + owner.percent, 0)
    if (total > 100) {
      ctx.addIssue({
        code: 'custom',
        path: ['owners'],
        message: `Declared ownership totals ${total.toFixed(2)}%. It cannot exceed 100%.`,
      })
    }
  })
```

The Server Action runs the same object and returns dotted paths:

```ts
'use server'
import { applicationSchema } from '@acme/contracts/application'

export async function submitApplication(_prev: FormState, payload: unknown): Promise<FormState> {
  const user = await requireUser()
  const parsed = applicationSchema.safeParse(payload)
  if (!parsed.success) {
    const fieldErrors: Record<string, string[]> = {}
    for (const issue of parsed.error.issues) {
      const path = issue.path.join('.')
      ;(fieldErrors[path] ??= []).push(issue.message)
    }
    return { status: 'error', fieldErrors }
  }
  const result = await onboarding.submit({
    application: parsed.data,
    submittedBy: user.id,
    idempotencyKey: `application:${user.id}:${parsed.data.registrationNumber}`,
  })
  return { status: 'success', caseRef: result.caseRef }
}
```

The form wires the resolver, the field array, and the server errors:

```tsx
'use client'
import { useActionState, useEffect, useRef, startTransition } from 'react'
import { useForm, useFieldArray } from 'react-hook-form'
import { zodResolver } from '@hookform/resolvers/zod'
import { applicationSchema, type Application } from '@acme/contracts/application'

export function ApplicationForm() {
  const [state, formAction, isPending] = useActionState(submitApplication, { status: 'idle' })
  const form = useForm<Application>({
    resolver: zodResolver(applicationSchema),
    mode: 'onBlur',
    reValidateMode: 'onChange',
    defaultValues: { owners: [{ name: '', percent: 25.01 }] },
  })
  const owners = useFieldArray({ control: form.control, name: 'owners' })
  const summary = useRef<HTMLDivElement>(null)

  useEffect(() => {
    if (state.status !== 'error' || !state.fieldErrors) return
    for (const [path, messages] of Object.entries(state.fieldErrors)) {
      form.setError(path as never, { type: 'server', message: messages[0] })
    }
    form.setFocus(Object.keys(state.fieldErrors)[0] as never)
    summary.current?.focus()
  }, [state, form])

  return (
    <form onSubmit={form.handleSubmit((data) => startTransition(() => formAction(data)))} noValidate>
      <div ref={summary} tabIndex={-1} role="alert" aria-live="assertive">
        {state.status === 'error' ? state.message : null}
      </div>
      <fieldset disabled={isPending}>
        <label htmlFor="legalName">Registered legal name</label>
        <input id="legalName" {...form.register('legalName')} aria-invalid={!!form.formState.errors.legalName} />
        {form.formState.errors.legalName && <p>{form.formState.errors.legalName.message}</p>}
        {/* owners.map(...) with register(`owners.${i}.name`) */}
        <button type="submit" aria-busy={isPending} disabled={isPending}>
          {isPending ? 'Submitting...' : 'Submit application'}
        </button>
      </fieldset>
    </form>
  )
}
```

Build the accessible field primitive **once**, so no call site can forget the association:

```tsx
'use client'
import { useId, type ReactNode } from 'react'

export function Field({ label, hint, error, children }: {
  label: string; hint?: string; error?: string
  children: (ids: { id: string; 'aria-invalid'?: true; 'aria-describedby'?: string }) => ReactNode
}) {
  const id = useId()
  const hintId = `${id}-hint`
  const errorId = `${id}-error`
  const describedBy = [hint ? hintId : null, error ? errorId : null].filter(Boolean).join(' ')
  return (
    <div>
      <label htmlFor={id}>{label}</label>
      {hint ? <p id={hintId}>{hint}</p> : null}
      {children({ id, ...(error ? { 'aria-invalid': true as const } : {}), ...(describedBy ? { 'aria-describedby': describedBy } : {}) })}
      {error ? <p id={errorId}>{error}</p> : null}
    </div>
  )
}
```

## Gotchas

- **`schema.pick()` drops `superRefine`.** Step slices validate fields but not object-level rules; the full schema must run on submit.
- **`defaultValues` is not validation.** A value typed as required but omitted from defaults makes the form dirty on mount and can hide errors.
- **`setError` with a path string is untyped.** Cast deliberately, or derive the path from the schema so a rename breaks the compiler.
- **A disabled submit button is a UX control, not concurrency control.** Make the server operation idempotent; a double submit must not create two cases.
- **`aria-describedby` replaces, not appends.** If you overwrite a hint id with the error id, the user loses the guidance.
- **Validating on every keystroke** tells someone their email is invalid while they are still typing it. Use `onBlur` then `onChange`.

## Production checklist

- [ ] One schema lives in a shared package imported by the form and the Server Action.
- [ ] Server re-validation runs on every request, including replayed ones.
- [ ] Cross-field rules are in `superRefine` with an explicit `path`.
- [ ] Errors set `aria-invalid`, keep the hint in `aria-describedby`, and are announced in a live region.
- [ ] Focus moves to the first invalid field after a failed submit.
- [ ] Submit is disabled while pending **and** the server is idempotent.
- [ ] Tests pin the drift cases: the prefixed registration number, the missing postcode, the ownership total.
