## TL;DR
Vue 3's Composition API and `<script setup>` allow grouping logic by feature rather than lifecycle option. Nuxt 3 extends this with auto-imports and server-side rendering (SSR) by default.

## Why it exists
The traditional Options API (`data`, `methods`, `computed`) forced related logic to be scattered across different parts of a component file. As components grew, maintenance became difficult. The Composition API solves this by allowing logic to be extracted into reusable functions (composables) and grouped naturally by feature.

## Mental model
**Reactivity as a primitive.** Variables are wrapped in `ref()` or `reactive()` to become observable. Changes to these variables automatically trigger DOM updates.

| Feature | Options API | Composition API (`<script setup>`) |
|---|---|---|
| **Logic Reuse** | Mixins (prone to name collisions) | Composables (clean, typed functions) |
| **Organization** | Grouped by option type | Grouped by feature |
| **TypeScript** | Difficult to type correctly | First-class, deep TS support |
| **Boilerplate** | High (export default, etc.) | Low (top-level declarations) |

## Do it
### Basic Component with `<script setup>`
```vue
<script setup lang="ts">
import { ref, computed } from 'vue'

const count = ref(0)
const doubleCount = computed(() => count.value * 2)

function increment() {
  count.value++
}
</script>

<template>
  <button @click="increment">Count is {{ count }} (Double: {{ doubleCount }})</button>
</template>
```

### Nuxt 3 Composable (`composables/useCounter.ts`)
```ts
export const useCounter = () => {
  const count = useState('count', () => 0)
  const increment = () => count.value++
  return { count, increment }
}
```

## Gotchas
- **Ref unwarpping**: Remember that `ref` values must be accessed via `.value` in JavaScript, but are automatically unwrapped in templates.
- **Reactive vs Ref**: Use `ref()` for primitive values and `reactive()` for objects/arrays that don't need re-assignment.
- **Nuxt Auto-imports**: While convenient, auto-imports can sometimes make it harder to trace where a function is defined; use IDE extensions (like Volar) for navigation.

## Production checklist
- [ ] Components use `<script setup>` for concise, performant Composition API usage.
- [ ] Logic shared across components is extracted into typed composables.
- [ ] Nuxt 3 auto-imports are used for standard composables and components.
- [ ] Reactive state is used sparingly and kept close to where it is consumed.
