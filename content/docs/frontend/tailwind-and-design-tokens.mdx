## TL;DR

- **Three layers:** a primitive palette, semantic tokens that name a job (`primary`, `muted`, `destructive`), and utilities that components consume (`bg-primary`, `text-muted-foreground`, `rounded-card`).
- **One theme block:** `@theme` in Tailwind v4 generates utilities from CSS variables. `@theme inline` keeps colour utilities pointed at `var(--primary)` so a `.dark` scope swaps values without touching components.
- **Contrast is a test, not an opinion:** measure every foreground/background pair in both themes and fail the build below 4.5:1 for text.

## Why it exists

A design system without tokens is a screenshot. The first sprint ships `bg-[#1E7A5F]` and `text-[#6B7280]` in eleven files. Then marketing asks for a warmer green, dark mode arrives, and someone changes nine of the eleven. The two leftovers are invisible in review and obvious to a user on the settings page. Tokens fix the shape of the problem: a component asks for the *role* ("primary surface", "muted text") and the theme decides the value.

Tailwind v4 made this easier by moving configuration into CSS. `@theme` is the source of truth; utilities are generated from it. The discipline that remains is naming roles rather than values and keeping every colour decision in one file.

## Mental model

**Primitive, semantic, component.** Primitives are the raw palette. Semantic tokens are aliases with intent. Components consume only semantic tokens. If a component needs a new colour, add a semantic token, not a hex value.

**`@theme` vs `@theme inline`.**

| Block | Use it for | Generated utility |
|---|---|---|
| `@theme` | Literal values: type scale, radii, durations | `text-body`, `rounded-card` |
| `@theme inline` | Values that are themselves `var(...)` | `bg-primary` -> `background-color: var(--primary)` |

With `inline`, the utility points at the variable rather than a resolved value, which is exactly what a theme scope needs.

**One theme scope.** Define `--primary` under `:root` and again under `.dark`. Components do not branch on theme; the variable does.

**Radius and type are tokens too.** The same rule applies to `rounded-card`, `rounded-control`, `text-body` and `--ease-ios`. A page that invents `rounded-[13px]` has left the system.

**Contrast is measured.** Relative luminance is computed for each pair, with translucent fills composited the way the browser paints them. The script fails the build; a human does not eyeball it.

## Do it

Keep the palette and the semantic mapping in one stylesheet. This is the shape used by this site:

```css
@import 'tailwindcss';

@custom-variant dark (&:where(.dark, .dark *):not(:where(.light, .light *)));

@theme {
  --radius-control: 0.75rem;
  --radius-panel: 1rem;
  --radius-card: 1.25rem;

  --text-body: 1.0625rem;
  --text-body--line-height: 1.375rem;
  --text-body--letter-spacing: -0.027rem;

  --duration-base: 260ms;
  --ease-ios: cubic-bezier(0.32, 0.72, 0, 1);
}

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-muted: var(--muted);
  --color-muted-foreground: var(--muted-foreground);
  --color-border: var(--border);
  --color-ring: var(--ring);
}

:root {
  --background: #fafaf8;
  --foreground: #0e1013;
  --primary: #1e7a5f;
  --primary-foreground: #ffffff;
  --muted: #f1f1ee;
  --muted-foreground: #5c5f63;
  --border: #e2e2dd;
  --ring: #1e7a5f;
}

.dark {
  --background: #0e1013;
  --foreground: #f4f4f1;
  --primary: #63c6a4;
  --primary-foreground: #08211a;
  --muted: #1a1d21;
  --muted-foreground: #a8adb4;
  --border: #2a2e34;
  --ring: #63c6a4;
}
```

A component then reads like a sentence, and contains no colour decision:

```tsx
export function Callout({ children }: { children: React.ReactNode }) {
  return (
    <aside className="rounded-panel border border-border bg-muted p-4 text-body text-muted-foreground">
      {children}
    </aside>
  )
}
```

Prove contrast in CI rather than in review. The script below is the idea; this repo's `scripts/contrast.mjs` is the full version and fails non-zero:

```js
const channel = (c) => {
  const s = c / 255
  return s <= 0.03928 ? s / 12.92 : ((s + 0.055) / 1.055) ** 2.4
}
const luminance = ([r, g, b]) => 0.2126 * channel(r) + 0.7152 * channel(g) + 0.0722 * channel(b)
const ratio = (a, b) => {
  const [hi, lo] = [luminance(a), luminance(b)].sort((x, y) => y - x)
  return (hi + 0.05) / (lo + 0.05)
}

const pairs = [
  { fg: [250, 250, 248], bg: [14, 16, 19], min: 4.5, name: 'foreground on background (dark)' },
  { fg: [92, 95, 99], bg: [250, 250, 248], min: 4.5, name: 'muted-foreground on background (light)' },
]

let failed = false
for (const pair of pairs) {
  const value = ratio(pair.fg, pair.bg)
  const ok = value >= pair.min
  console.log(`${ok ? 'PASS' : 'FAIL'} ${pair.name}: ${value.toFixed(2)}:1 (min ${pair.min})`)
  if (!ok) failed = true
}
process.exit(failed ? 1 : 0)
```

The snippets above are illustrative and not run in this repo; the page records the verified library versions only.

## Gotchas

- **A primitive used directly is a leak.** `bg-jade-600` in a component bypasses theming; wrap it in a semantic token.
- **`@theme` resolves at build time.** If a colour changes at runtime, map it with `@theme inline` and a CSS variable instead.
- **A single `.dark` override is not enough** if a library ships unlayered colours. Map the library's variables to your tokens with equal or higher specificity, after its stylesheet.
- **Arbitrary values multiply.** One `text-[13px]` is a review smell; ten are a second type scale.
- **Opacity is not free.** `text-muted-foreground/60` composites differently on each background; measure the result, not the token.
- **Red means error.** If red is also a brand accent, the error state stops being a signal.

## Production checklist

- [ ] One token file owns every colour, radius, type step, duration and easing.
- [ ] Components use semantic utilities only; no hex values and no arbitrary colour classes.
- [ ] The theme switch changes variables in one scope, not `dark:` variants across components.
- [ ] A script measures every text and UI pair in both themes and fails below the minimum.
- [ ] Library styles are mapped to the tokens after their own stylesheet.
- [ ] The token file is reviewed like an API: additions are named for a role.
