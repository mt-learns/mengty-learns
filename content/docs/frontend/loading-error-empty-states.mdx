## TL;DR
Every asynchronous UI region has four states: **Loading** (layout-matching skeleton), **Error** (actionable failure message + retry), **Empty** (zero-data guidance + CTA), and **Success** (rendered content). Design all four before shipping.

## Why it exists
Interfaces written with only the "Success" state in mind break the moment network latency, server failures, or empty collections occur. A spinner in the middle of a page or a blank screen causes user confusion and unnecessary support tickets. Treating the four states as standard contracts makes applications robust and predictable.

## The Four States Reference

| State | Purpose | UX Rule |
|---|---|---|
| **Loading** | Signal progress without layout shift | Use skeleton blocks matching final dimensions; avoid spinners for page transitions. |
| **Error** | Explain what failed and how to recover | Plain language, persistent error code if helpful, and a clear "Try again" action. |
| **Empty** | Guide the user when zero items exist | Contextual illustration/icon, clear explanation, and a primary call to action (e.g., "Create item"). |
| **Success** | Deliver the expected content | Fast render, proper aria attributes, and smooth transition. |

## Do it
### 1. Loading Skeletons
```tsx
export function TableSkeleton() {
  return (
    <div className="animate-pulse space-y-3">
      <div className="h-8 w-1/3 rounded-card bg-muted" />
      <div className="h-48 w-full rounded-card bg-muted" />
    </div>
  )
}
```

### 2. Error Boundaries
```tsx
'use client'
export function ErrorState({ error, reset }: { error: Error & { digest?: string }; reset: () => void }) {
  return (
    <div role="alert" className="rounded-card border border-border p-6 text-center">
      <h3 className="text-body font-semibold">Something went wrong</h3>
      <p className="text-muted-foreground">{error.message}</p>
      <button onClick={reset} className="mt-4 rounded-control bg-primary px-4 py-2 text-primary-foreground">
        Try again
      </button>
    </div>
  )
}
```

### 3. Empty States
```tsx
export function EmptyState({ title, description, action }: { title: string; description: string; action?: React.ReactNode }) {
  return (
    <div className="rounded-card border border-dashed border-border p-12 text-center">
      <h3 className="text-body font-semibold">{title}</h3>
      <p className="mt-1 text-muted-foreground">{description}</p>
      {action && <div className="mt-4">{action}</div>}
    </div>
  )
}
```

## Gotchas
- **Spinners everywhere** cause layout thrashing and anxiety; use skeletons that match final layout.
- **Generic error messages** like "An error occurred" leave users helpless; state what failed and how to fix it.
- **Empty states without CTAs** are dead ends; always give the user a next step.
- **Hiding loading states** on fast connections hides regressions that slow connections will suffer from.

## Production checklist
- [ ] Every asynchronous query has a matching skeleton that preserves container dimensions.
- [ ] Error boundaries catch render failures and provide a recovery action (`reset`).
- [ ] Empty states guide the user toward creating or finding data with a clear CTA.
- [ ] Screen readers announce loading and error state changes via ARIA live regions.
- [ ] Network failures and 4xx/5xx responses are tested in staging.
