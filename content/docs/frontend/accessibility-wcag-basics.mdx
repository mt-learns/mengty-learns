## TL;DR
WCAG 2.2 organizes success criteria around four principles—PERCEIVABLE, OPERABLE, UNDERSTANDABLE, ROBUST—each with testable criteria. Prioritize AA compliance; fix critical (A) blockers first, then iterate toward AA for public-facing products.

## Why it exists
Many teams treat accessibility as a checklist feature rather than a structural requirement. Without a shared mental model of the four WCAG principles, developers add ARIA labels that don't fix the underlying barrier, or they pass audit tools while still excluding screen-reader users. A principles-first approach ensures every fix addresses a real exclusion.

## Mental model
**The four WCAG principles, in order of priority:**

| Principle | Mnemonic | Core idea | AA focus |
|---|---|---|---|
| **Perceivable** | P | Information and UI components must be presentable to users in ways they can perceive. Provide text alternatives, captions, adaptable layout, and distinguishable colors. | 1.4.3 Contrast (Minimum), 1.2.2 Captions (Live), 1.1.1 Non-text Content |
| **Operable** | O | UI components and navigation must be operable. Ensure keyboard access, enough time, no seizures, and clear navigation. | 2.1.1 Keyboard, 2.4.3 Focus Order, 2.4.7 Focus Visible, 2.3.1 Three Flashes |
| **Understandable** | U | Information and the operation of the user interface must be understandable. Make text readable, predictable, and help users avoid and correct mistakes. | 3.1.1 Language of Page, 3.2.1 On Input, 3.3.1 Error Identification |
| **Robust** | R | Content must be robust enough that it can be reliably interpreted by a wide variety of user agents, including assistive technologies. Use clean markup and valid HTML. | 4.1.1 Parsing, 4.1.2 Name, Role, Value |

**Rule of thumb:** start with Perceivable (color contrast, alt text), then Operable (keyboard, focus), then Understandable (language, error messages), then Robust (markup validity).

## Do it
### 1. Color contrast
- Measure every foreground/background pair in both light and dark themes.
- Text: ≥ 4.5:1 (AA), ≥ 3:1 for large text (≥ 18pt or 14pt bold).
- UI graphics: ≥ 3:1.
- Use a script (e.g., `scripts/contrast.mjs`) in CI; fail the build on failure.

### 2. Keyboard accessibility
- Test every interactive element with Tab/Shift+Tab alone.
- Ensure focus is visible (not just `outline: none`).
- Logical focus order: match visual layout or use `order` consciously.
- Trap focus in modals/dialogs and restore focus on close.

### 3. Alt text for images
- Decorative images: `alt=""` (empty string) or CSS background.
- Informative images: brief, descriptive alt text (< 125 characters).
- Complex charts: provide a data table or long description via `aria-describedby`.

### 4. Focus management
- `focus()` programmatically only after user gesture or in `useEffect` with a clear trigger.
- Never trap focus arbitrarily; if you do, provide an escape.
- Announce modal dialogs with `aria-modal` and a role="alert" live region.

### 5. Language declaration
- Add `lang="en"` (or your language code) to `<html>`.
- Use `lang` attribute on nested elements for content in other languages.

## Gotchas
- **`color: red` alone does not convey error.** Combine with text, icons, or programmatic error state.
- **Screen readers read DOM order, not visual order.** A reordered flex layout can cause confusing navigation.
- **`aria-label` overrides visible text.** If you add an `aria-label`, ensure it makes sense on its own.
- **WCAG A is the floor, not the ceiling.** Meeting A does not mean your site is accessible.
- **Automated tools catch ~30–50% of issues.** Manual testing with screen readers is essential.

## Production checklist
- [ ] Color contrast ≥ 4.5:1 for text and ≥ 3:1 for UI graphics, in both light and dark themes.
- [ ] All interactive elements reachable via keyboard only (Tab/Shift+Tab).
- [ ] Focus ring visible and meets 3:1 contrast against UI.
- [ ] Meaningful `alt` text on all informative images; `alt=""` on decorative images.
- [ ] `lang` attribute on `<html>` and on content in other languages.
- [ ] No content that flashes more than 3 times per second (avoid `animation: flash`).
- [ ] Error messages identified with `aria-invalid` and described via `aria-describedby`.
- [ ] Form fields linked to labels via `for`/`id` pairing.
- [ ] Focus is not trapped arbitrarily; modals provide an escape.
