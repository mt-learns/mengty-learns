## TL;DR
Filters, pagination, and active tabs belong in the URL search parameters, not component `useState`. `nuqs` provides type-safe parsers (`parseAsInteger`, `parseAsString`) that sync React state with the browser URL cleanly.

## Why it exists
When filters live in local `useState`, sharing a link with a colleague resets their view. Hitting the browser back button loses the current search term. Hand-parsing `URLSearchParams` in every component leads to repetitive boilerplate and string-coercion bugs. `nuqs` treats URL query parameters as first-class typed state.

## Mental model
**URL as single source of truth.** The URL is global, shareable state. Components read search params during SSR, render initial state without a flash, and update params client-side without full reloads.

| Feature | `useState` | `nuqs` (URL state) |
|---|---|---|
| **Shareable** | No | Yes (copy URL) |
| **Back/Forward** | No | Yes (native history) |
| **SSR-friendly** | Needs hydration sync | Instant on first paint |
| **Persistence** | Lost on reload | Survives reloads |

## Do it
### Define parsers and hooks
```tsx
'use client'
import { useQueryState, parseAsString, parseAsInteger } from 'nuqs'

export function SearchFilter() {
  const [search, setSearch] = useQueryState(
    'q',
    parseAsString.withDefault('').withOptions({ shallow: false })
  )
  const [page, setPage] = useQueryState(
    'page',
    parseAsInteger.withDefault(1)
  )

  return (
    <div>
      <input
        value={search}
        onChange={(e) => setSearch(e.target.value)}
        placeholder="Search accounts..."
      />
      <button onClick={() => setPage(page + 1)}>Next Page (Page {page})</button>
    </div>
  )
}
```

## Gotchas
- **Forgetting to debounce** fast typing can flood browser history with query updates; use `{ throttleMs: 300 }`.
- **Server component mismatch** occurs if server and client parse query parameters with differing default values.
- **Shallow routing vs server re-fetch**: setting `shallow: false` triggers a Server Component re-fetch when params change, which is required when data fetching depends on server-side search params.

## Production checklist
- [ ] Filters, sorting, and pagination live in URL search parameters rather than `useState`.
- [ ] `nuqs` parsers validate types (`parseAsInteger`, `parseAsString`, `parseAsArrayOf`).
- [ ] Fast inputs use throttling (`throttleMs`) to avoid history stack pollution.
- [ ] Server components correctly receive and react to updated search params.
- [ ] Shareable links tested across browsers.
