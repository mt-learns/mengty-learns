## TL;DR
Handoff is a conversation, not a document. Use design tokens for colors and spacing, define shared component names, and document interaction states (hover, active, loading) before code begins.

## Why it exists
Without a structured handoff, engineers guess at spacing, ignore edge cases like loading states, and hard-code hex values that drift from the design system. This leads to high rework, inconsistent UI, and frustration between disciplines. A shared system of tokens and components ensures what is designed is what is built.

## Mental model
**Shared Language.** Designers and engineers use the same names for the same things.

| Concept | Design Tool (Figma) | Implementation (Tailwind) |
|---|---|---|
| **Color** | Primary / 600 | `--color-primary` |
| **Spacing** | 16px (Step 4) | `p-4` / `1rem` |
| **Component** | Card / Default | `<Card />` |
| **State** | Pressed | `:active` |

## Do it
### 1. Design Tokens First
Agree on a naming convention for colors, typography, and spacing. Use these tokens in Figma variables and map them directly to Tailwind `theme` variables.

### 2. Interaction Audit
Don't just hand off "the screen". Hand off:
- **Hover/Active/Focused** states for every button and link.
- **Loading/Empty/Error** states for data-driven regions.
- **Responsive behavior**: how the layout changes from mobile to desktop.

### 3. Shared Component Library
Document common UI patterns (buttons, inputs, cards) in a shared library. Reference the same component names in design and code.

## Gotchas
- **Hard-coded hex values** in Figma are "design debt"; they must be replaced with tokens before handoff.
- **Missing edge cases** (e.g. long text in a narrow column) cause broken layouts during development.
- **One-way handoff** (designers "tossing it over the wall") always leads to rework.

## Production checklist
- [ ] Design tokens (colors, type, spacing) are synchronized between Figma and CSS.
- [ ] Every component has defined hover, focus, and active states.
- [ ] Edge cases (loading, empty, error, long text) are documented.
- [ ] Responsive breakpoints and container behavior are clearly defined.
- [ ] Engineers have reviewed the designs for technical feasibility before they are finalized.
