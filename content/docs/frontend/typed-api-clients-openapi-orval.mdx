## TL;DR
Never write manual fetch wrappers or TypeScript interfaces for backend endpoints. Generate typed TanStack Query hooks and client SDKs automatically from your OpenAPI specification using `Orval`.

## Why it exists
Hand-writing `fetch('/api/v1/accounts/' + id)` and casting responses with `as Account` creates silent API drift. When a backend engineer renames `accountId` to `id`, TypeScript remains unaware until runtime errors occur in production. Generating types and hooks from a single OpenAPI schema ensures frontend and backend contracts stay synchronized automatically.

## Mental model
**Contract-first development.** The OpenAPI YAML or JSON specification is the single source of truth. Backend and frontend both validate against it.

| Step | Action | Tool |
|---|---|---|
| **1. Spec** | Define endpoints, schemas, and responses | OpenAPI 3.1 / Swagger |
| **2. Generate** | Produce typed fetchers and React Query hooks | Orval |
| **3. Consume** | Call `useGetAccountQuery(id)` in components | React / TanStack Query |

## Do it
### Orval Configuration (`orval.config.ts`)
```ts
import { defineConfig } from 'orval'

export default defineConfig({
  api: {
    input: './openapi.yaml',
    output: {
      mode: 'tags',
      target: './src/api/generated',
      schemas: './src/api/model',
      client: 'react-query',
      prettier: true,
    },
  },
})
```

### Consuming in Components
```tsx
'use client'
import { useGetAccount } from '@/api/generated/accounts/accounts'

export function AccountProfile({ accountId }: { accountId: string }) {
  const { data, isLoading, error } = useGetAccount(accountId)

  if (isLoading) return <p>Loading account...</p>
  if (error || !data) return <p>Failed to load account.</p>

  return <div><h2>{data.name}</h2><p>Balance: {data.balance}</p></div>
}
```

## Gotchas
- **Committing generated files** into git can cause merge conflicts; either gitignore them and generate during build, or commit them so CI can build without external API access.
- **Outdated specs** generated locally will fail in CI if the backend spec is newer; run generation during the CI pipeline build step.
- **Over-fetching** can occur if OpenAPI tags are too broad; scope Orval output to specific tags or paths.

## Production checklist
- [ ] OpenAPI specification file (`openapi.yaml`) is maintained as the single source of truth.
- [ ] Orval is configured to generate typed TanStack Query hooks and models.
- [ ] Code generation runs in CI before the TypeScript typecheck and build steps.
- [ ] Manual `fetch` wrappers for REST endpoints are removed in favor of generated hooks.
