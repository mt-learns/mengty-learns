## TL;DR
A network perimeter answers *where* a packet came from, not *who* sent it. Defend **external APIs** with a gateway, WAF, per-identity rate limits, and OAuth/mTLS; defend **internal APIs** with **mTLS workload identity**, **scoped tokens**, and **per-endpoint authorization** so one compromised pod cannot pivot across your mesh.

## Why it exists
Teams frequently put strong OAuth, WAF, and rate limits on their public gateway while leaving internal service-to-service HTTP calls completely unauthenticated. The first RCE in an edge-adjacent pod (such as a file parser) then gets free access to internal admin and payment endpoints with zero audit actor.

## Do it

| Control | External / Partner Edge | Internal Service Mesh |
|---|---|---|
| **Identity** | OIDC user or partner client + mTLS | Workload identity (mTLS / SPIFFE) + narrowed JWT |
| **Transport** | Public TLS 1.3 | Strict mTLS between pods |
| **Authorization** | Coarse scopes at gateway + object check in service | Default-deny mesh policy + per-route `@PreAuthorize`/guard |
| **Abuse protection** | WAF, schema validation, per-identity rate limits | Circuit breakers, bulkheads, per-caller quotas |

## Gotchas
- **Static API keys as sole auth:** Long-lived API keys without expiry or scopes leak into repos and logs; pair partner mTLS or OAuth client credentials instead.
- **Checking auth only at the gateway:** If an internal service skips token/audience checks, any lateral call inside the cluster bypasses authorization.
- **Missing object-level checks (BOLA):** Validating `orders.read` scope without filtering `WHERE tenant_id = token.tenant_id` lets Partner A read Partner B's orders.

## Production checklist
- [ ] Enforce strict mTLS (`STRICT` peer authentication) and default-deny network/mesh policies internally.
- [ ] Require authentication and explicit authorization checks on every internal route, including admin/override endpoints.
- [ ] Key external rate limits on authenticated client/partner ID rather than IP alone.
- [ ] Write negative tests verifying 401 (missing/wrong audience), 403 (missing role), and 404/403 (cross-tenant access).
