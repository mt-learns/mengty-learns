## TL;DR
**XSS** happens when untrusted input is interpreted as executable script in a victim's browser (**Reflected**, **Stored**, or **DOM-based**). Prevent it primarily with **context-aware output encoding** (plus sanitizing rich HTML with DOMPurify and rejecting `javascript:` URLs), and add a **nonce + `'strict-dynamic'` Content Security Policy (CSP)** as defense in depth.

## Intent
<Intent>
Distinguish Reflected, Stored, and DOM XSS, know where React's automatic escaping stops, and pair context-aware encoding with a strict nonce-based CSP.
</Intent>

## Problem
Many developers assume "React escapes everything" or "HTML-encoding `<` and `>` is enough". In reality, passing a user-supplied URL like `javascript:alert(1)` to `<a href={url}>`, using `dangerouslySetInnerHTML` without sanitization, or writing to `element.innerHTML` still gives attackers full script execution in the victim's origin.

## Solution
Layer primary encoding/sanitization with a strong browser CSP (ASVS V1 & V3):

1. **Context-aware output encoding:** Encode for the exact sink—HTML body (`&lt;`), HTML attribute, JavaScript data (JSON serialization, never string interpolation inside `<script>`), and URLs (validate `https:` / `http:` scheme before rendering `href`/`src`).
2. **React's boundary:** JSX `{userInput}` is safe for text nodes. Never pass unsanitized HTML to `dangerouslySetInnerHTML` (sanitize first with DOMPurify), and always validate URL schemes before rendering `<a href={userUrl}>`.
3. **Strict CSP (defense in depth):** Generate a fresh cryptographic `nonce` per response and set `script-src 'nonce-<random>' 'strict-dynamic'; object-src 'none'; base-uri 'none';`. Avoid `'unsafe-inline'` and `'unsafe-eval'`.

## Real-world analogy
<Analogy>
**Output encoding** is putting a visitor's handwritten note inside a sealed glass display case so it can only be read as text, never mistaken for a PA-system command. **CSP with nonces** is requiring a one-time wax seal on every legitimate announcement—any forged note slipped under the door lacks the seal and is ignored.
</Analogy>

## Code
Watch out for React's two classic escape hatches (`dangerouslySetInnerHTML` and unvalidated `href`):

```tsx
// UNSAFE: raw HTML injection and unvalidated URL scheme (allows javascript:alert(1))
function UnsafeProfile({ bioHtml, websiteUrl }: { bioHtml: string; websiteUrl: string }) {
  return (
    <div>
      <div dangerouslySetInnerHTML={{ __html: bioHtml }} />
      <a href={websiteUrl}>Website</a>
    </div>
  );
}

// SAFE: sanitize rich HTML and enforce https:/http: URL allowlist (ASVS V1, V3)
import DOMPurify from 'dompurify';

function safeHref(raw: string): string {
  try {
    const parsed = new URL(raw);
    return parsed.protocol === 'https:' || parsed.protocol === 'http:' ? parsed.toString() : '#';
  } catch {
    return '#';
  }
}

function SafeProfile({ bioHtml, websiteUrl }: { bioHtml: string; websiteUrl: string }) {
  const cleanHtml = DOMPurify.sanitize(bioHtml);
  return (
    <div>
      <div dangerouslySetInnerHTML={{ __html: cleanHtml }} />
      <a href={safeHref(websiteUrl)} rel="noopener noreferrer">Website</a>
    </div>
  );
}
```

## When to use / when to avoid
<Checklist
  use={[
    'Use framework auto-escaping (React JSX text nodes) for plain text, and DOMPurify when you must render user-authored HTML.',
    'Validate URL protocols (https:/http:) before placing user input into href, src, or window.location.',
    'Deploy a nonce + strict-dynamic CSP on dynamic HTML responses to contain any missed encoding bug.',
  ]}
  avoid={[
    'Never rely on CSP alone while leaving raw innerHTML or dangerouslySetInnerHTML unescaped.',
    'Never add unsafe-inline or wildcard domains (https: *) to script-src—they defeat CSP.',
  ]}
/>

## How to implement
<Steps>
  <Step>
    ### Audit dangerous sinks
    Search the codebase for `dangerouslySetInnerHTML`, `innerHTML`, `document.write`, `eval`, and dynamic `href`/`src` props.
  </Step>
  <Step>
    ### Enforce URL and HTML sanitization
    Wrap rich HTML with DOMPurify and reject non-`http(s):` URLs.
  </Step>
  <Step>
    ### Roll out CSP in Report-Only first
    Start with `Content-Security-Policy-Report-Only`, inspect violation reports, then switch to enforcing mode.
  </Step>
</Steps>
