## TL;DR
**CSRF** abuses a victim's browser to send authenticated requests to your server; **SSRF** abuses your server to send requests into your private network or cloud metadata (`169.254.169.254`). Defend CSRF with **`SameSite` cookies + CSRF tokens + `Origin`/`Sec-Fetch-Site` checks**, and defend SSRF with **strict URL allowlists, disabled redirects, and pinned-IP private/metadata blocks**.

## Intent
<Intent>
Separate browser-side request forgery (CSRF) from server-side request forgery (SSRF), and apply layered defenses that survive edge cases like subdomains and DNS rebinding.
</Intent>

## Problem
Both attacks exploit **confused-deputy trust**:
- In **CSRF**, your backend trusts cookies that the browser attaches automatically, even when the request was triggered by `evil.example`.
- In **SSRF** (now part of `A01:2025 Broken Access Control`), your backend fetches a user-supplied URL (webhook, avatar importer, PDF generator) and unwittingly reaches internal admin APIs or cloud IMDSv1 credentials.

## Solution
### Stopping CSRF
1. **Use `SameSite=Lax` (or `Strict`)** on session cookies so cross-site `POST` forms do not carry cookies.
2. **Require an unpredictable CSRF token** (or custom header validated with `Origin` / `Sec-Fetch-Site` checks) on every state-changing `POST`/`PUT`/`PATCH`/`DELETE` route.
3. **Never mutate state on `GET` requests** (because `SameSite=Lax` still sends cookies on top-level `GET` navigations).

### Stopping SSRF
1. **Use a domain/scheme allowlist** (`https:` only, exact allowed hosts) whenever business logic permits.
2. **Block private, loopback, link-local (`169.254.0.0/16`), and IPv6 ULA ranges** after DNS resolution, and **connect to the resolved IP directly** (preventing DNS rebinding).
3. **Disable automatic HTTP redirects** (or re-validate every redirect target) and enforce cloud **IMDSv2** (session-token required).

## Real-world analogy
<Analogy>
**CSRF** is someone forging your signature by slipping a bank transfer form into a stack of harmless flyers you sign without looking. **SSRF** is tricking a company receptionist into walking into the locked server room to read a sticky note on the wall because they have badge access and you don't.
</Analogy>

## Code
Validating `Origin` for CSRF and defending SSRF against private/link-local IPs, IPv4-mapped IPv6, and DNS-rebinding TOCTOU:

> Hand-rolled IP filters are easy to get wrong. In production, prefer an **egress proxy with a domain allowlist** (such as Envoy or Smokescreen) plus network egress rules; use the snippet below only when you must validate arbitrary URLs in Node.js.

```ts
// UNSAFE: fetches any URL from the user with redirects enabled
const unsafeRes = await fetch(req.body.webhookUrl);

// SAFE (not run): resolve once, validate every IP (incl. IPv4-mapped IPv6),
// pin the validated IP on connect to prevent DNS-rebinding TOCTOU, and disable redirects.
import { lookup } from 'node:dns/promises';
import net from 'node:net';
import { Agent, fetch as undiciFetch } from 'undici';

function ipv4ToInt(ip: string): number {
  return ip.split('.').reduce((acc, oct) => ((acc << 8) | Number(oct)) >>> 0, 0);
}

function isBlockedIPv4(ip: string): boolean {
  const n = ipv4ToInt(ip);
  const inCidr = (base: string, bits: number) => {
    const mask = bits === 0 ? 0 : (~0 << (32 - bits)) >>> 0;
    return (n & mask) === (ipv4ToInt(base) & mask);
  };
  return (
    inCidr('0.0.0.0', 8) ||       // "this" network
    inCidr('10.0.0.0', 8) ||      // RFC 1918
    inCidr('100.64.0.0', 10) ||   // CGNAT (RFC 6598)
    inCidr('127.0.0.0', 8) ||     // loopback
    inCidr('169.254.0.0', 16) ||  // link-local / cloud IMDS
    inCidr('172.16.0.0', 12) ||   // RFC 1918
    inCidr('192.168.0.0', 16) ||  // RFC 1918
    inCidr('224.0.0.0', 4)        // multicast & reserved
  );
}

function parseIPv6Groups(ip: string): number[] {
  const [head, tail = ''] = ip.toLowerCase().split('::');
  const expand = (part: string) =>
    part === '' ? [] : part.split(':').flatMap((g) => {
      if (g.includes('.')) {
        const v4 = ipv4ToInt(g);
        return [(v4 >>> 16) & 0xffff, v4 & 0xffff];
      }
      return [parseInt(g, 16)];
    });
  const h = expand(head);
  const t = expand(tail);
  const missing = 8 - (h.length + t.length);
  return [...h, ...Array(missing).fill(0), ...t];
}

function isBlockedIp(ip: string): boolean {
  if (net.isIPv4(ip)) return isBlockedIPv4(ip);
  if (!net.isIPv6(ip)) return true;
  const g = parseIPv6Groups(ip);
  const isZeroPrefix = g[0] === 0 && g[1] === 0 && g[2] === 0 && g[3] === 0 && g[4] === 0;
  if (isZeroPrefix && g[5] === 0 && g[6] === 0 && (g[7] === 0 || g[7] === 1)) return true; // :: and ::1
  if (isZeroPrefix && g[5] === 0xffff) {
    const v4 = `${g[6] >>> 8}.${g[6] & 0xff}.${g[7] >>> 8}.${g[7] & 0xff}`;
    return isBlockedIPv4(v4); // IPv4-mapped IPv6 (e.g. ::ffff:127.0.0.1)
  }
  if ((g[0] & 0xffc0) === 0xfe80) return true; // link-local fe80::/10
  if ((g[0] & 0xfe00) === 0xfc00) return true; // ULA fc00::/7
  if ((g[0] & 0xff00) === 0xff00) return true; // multicast ff00::/8
  return false;
}

export async function safeFetchWebhook(rawUrl: string) {
  const url = new URL(rawUrl);
  if (url.protocol !== 'https:') throw new Error('Only HTTPS allowed');
  const records = await lookup(url.hostname, { all: true });
  if (records.length === 0 || records.some((r) => isBlockedIp(r.address))) {
    throw new Error('Blocked private, link-local, or metadata IP');
  }
  const pinned = records[0];
  const dispatcher = new Agent({
    connect: {
      lookup: (_host, _opts, cb) => cb(null, pinned.address, pinned.family),
    },
  });
  try {
    return await undiciFetch(url, { dispatcher, redirect: 'error' });
  } finally {
    await dispatcher.close();
  }
}
```

## When to use / when to avoid

  use={[
    'Use SameSite=Lax + CSRF token + Origin/Sec-Fetch-Site validation on all cookie-authenticated mutations.',
    'Use an explicit domain allowlist wherever possible for server-side outbound fetches.',
    'Enable IMDSv2 on cloud VMs and block 169.254.169.254 from application egress.',

  avoid={[

## How to implement
<Steps>
  <Step>
    ### Harden cookies and state-changing routes
    Set `SameSite=Lax; HttpOnly; Secure` and verify `Origin` / `Sec-Fetch-Site` + CSRF token on `POST`/`PUT`/`DELETE`.
  </Step>
  <Step>
    ### Route outbound fetches through a safe client
    Centralize `fetch` calls for user URLs behind an allowlist, DNS IP check, and `redirect: 'error'`.
  </Step>
  <Step>
    ### Enforce network-level egress controls
    Use Kubernetes `NetworkPolicy` or cloud security groups so app pods cannot reach internal metadata IPs at all.
  </Step>
</Steps>
