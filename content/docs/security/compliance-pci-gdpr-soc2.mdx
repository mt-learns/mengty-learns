## TL;DR
*Engineering overview, not legal advice.* Compliance obligations attach to **data** and **controls**. Shrink **PCI DSS** scope by tokenizing card data at the edge, satisfy **GDPR** erasure with **crypto-shredding** and synthetic test data, and automate **SOC 2** evidence directly in your CI/CD pipeline.

## Why it exists
Treating compliance as an annual spreadsheet exercise fails during audits: raw PII leaks into debug logs, immutable audit trails conflict with deletion requests, and 90-day CI logs expire before auditors ask for Q1 release approvals. Building controls into architecture makes compliance automatic.

## Mental model
Minimize where sensitive data can exist, and separate **event evidence** from **personal payloads**.

## Do it

| Standard | Core engineering demand | Architectural pattern |
|---|---|---|
| **PCI DSS 4.x** | Protect cardholder data (PAN); prevent log leaks & client-side script tampering | Tokenize at PSP/edge; never store or log PANs; inventory & SRI-check payment scripts |
| **GDPR** | Data minimization, purpose limitation, and timely erasure (Art. 17) | Store PII in one place; use **synthetic data** in non-prod; use **crypto-shredding** for backups/logs |
| **SOC 2** | Prove security & change controls operated continuously over time | Enforce branch protection + 1+ review; emit immutable CI evidence bundles keyed by digest |

## Gotchas
- **Debug logging full domain objects:** A single `JSON.stringify(paymentAttempt)` in an error handler can copy millions of sensitive fields into log aggregators and cold backups. Redact at the serializer level.
- **Masking only names in UAT:** Copying production databases to staging with names replaced by `User_001` is still pseudonymized personal data if addresses, birth dates, or transaction histories remain.
- **Relying on default 90-day CI log retention:** Export test, scan, and PR approval artifacts to immutable long-term storage if your audit window is 1–7 years.

## Production checklist
- [ ] Keep raw payment card numbers (PANs) out of application databases, queues, and logs via edge tokenization.
- [ ] Never put raw PII into immutable audit log payloads—log a subject ID and payload hash instead.
- [ ] Use generated synthetic datasets in dev/staging/CI instead of production database dumps.
- [ ] Emit PR approval, test, and SBOM/scan evidence automatically in CI on every production release.
