## Intent

<Intent>
Turn security from a manual pre-release meeting into **automated, blocking code gates** ordered from fastest (pre-commit and SAST) to last-mile enforcement (Kyverno admission control and runtime detection).
</Intent>

## Problem

Manual security sign-offs before release either slow delivery to a crawl or get bypassed under deadline pressure. Conversely, turning on every scanner in "warn-only" mode creates a wall of red alerts that everyone ignores.

## Solution

Layer controls at four checkpoints so each catches what the previous layer cannot see:

1. **Pre-commit & fast PR checks (seconds):** `gitleaks` blocks secrets before they hit Git history; linters, SAST (Semgrep), SCA (`trivy fs` with `--ignore-unfixed`), and IaC scanners (`checkov` / `trivy config`) block high-severity issues early.
2. **Build, SBOM & signing (minutes):** Build an immutable image, scan OS/app packages with `trivy image`, generate a CycloneDX SBOM (Syft), and sign the `sha256:` digest with **Cosign**.
3. **Admission control (deploy time):** **Kyverno** verifies the Cosign signature, rejects `:latest` tags, and enforces non-root + resource limits before a Pod schedules—covering even out-of-band `kubectl` changes.
4. **Runtime detection (continuous):** **Falco** and cluster audit logs watch for unexpected shells, privilege escalation, or anomalous egress and alert the SIEM.

## Real-world analogy

<Analogy>
Think of airport security: your passport is checked at booking (**pre-commit**), luggage is X-rayed at the terminal (**SAST/SCA/Trivy**), boarding passes are stamped (**Cosign signature**), the gate agent scans the stamp before you board (**Kyverno admission**), and air marshals monitor in-flight behavior (**Falco runtime**).
</Analogy>

## Structure

Example CI image scan and signing commands:

```bash
# Scan filesystem dependencies and container image for actionable CVEs (not run)
trivy fs --exit-code 1 --severity CRITICAL,HIGH --ignore-unfixed .
trivy image --exit-code 1 --severity CRITICAL --ignore-unfixed app@sha256:...

# Sign the immutable digest with Cosign (not run)
cosign sign --yes registry.example.com/apps/payment@sha256:...
```

## When to use / when to avoid

- **Use full gated DevSecOps** for production services, multi-team clusters, and regulated workloads.
- **Avoid heavy blocking gates on day-one prototypes** if rulesets aren't tuned yet—start with secret scanning (`gitleaks`) + dependency scanning (`trivy fs --ignore-unfixed`), then add signing and admission policies before going live.

## Pros / Cons

- **Pros:** Fast developer feedback; tamper-evident supply chain (SBOM + Cosign); last-mile protection via Kyverno even if someone bypasses CI.
- **Cons:** Requires tuning rulesets and maintaining an expiring exception workflow so false positives do not stall legitimate releases.
