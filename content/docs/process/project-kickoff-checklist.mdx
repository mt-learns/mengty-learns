## TL;DR
Before writing business features, lock down **10 baseline practices**: branching rules, secret hygiene, modular layout, lint/format hooks, CI gates, safe CD, structured observability, ADR/README docs, code review norms, and a shared **Definition of Done**.

## The 10-step kickoff checklist

| # | Area | Day-1 baseline | Reference |
|---|---|---|---|
| **1** | **Repo & branching** | Trunk-based (`main` + short-lived branches), branch protection, no direct push to `main` | [Git Cheatsheet](/docs/foundations/git-cheatsheet) |
| **2** | **Env & secrets** | `.env.example` committed, `.env` gitignored, pre-commit secret scan (`gitleaks`), OIDC over static keys | [Secrets Management](/docs/security/secrets-management) |
| **3** | **Project structure** | Cohesive module layout, clear separation of domain logic from framework/I/O | [Compare Styles](/docs/architecture/compare-styles) |
| **4** | **Lint & formatting** | `eslint`, `prettier`, `tsc --noEmit` enforced in CI (and optional fast pre-commit hook) | [DoR & DoD Gates](/docs/process/dor-dod-quality-gates) |
| **5** | **CI pipeline** | Every PR runs lint, typecheck, unit/integration tests, and dependency/container scans | [Pipeline Anatomy](/docs/ci-cd/pipeline-anatomy) |
| **6** | **CD & rollback** | Immutable build artifacts, expand/contract migrations, feature flags or tag-based rollback | [Deploy & Rollback](/docs/ci-cd/deploy-and-rollback) |
| **7** | **Observability** | Structured JSON logs with correlation IDs, `/healthz` + `/readyz`, error rate & p95 latency alerts | [Observability](/docs/foundations/observability) |
| **8** | **Docs & ADRs** | Working local setup `README.md` + `docs/adr/` template for key trade-offs | [Write an ADR](/docs/process/adr) |
| **9** | **Code review** | Small PRs (< 400 lines), explicit checklist, constructive feedback, 1+ required approval | [Code Review](/docs/process/code-review) |
| **10** | **Definition of Done** | Shared contract: tests + scans green, docs updated, monitored in prod, rollback tested | [Idea to Production](/docs/process/idea-to-production) |

## "Done" stages people confuse

| Claim | Reality | User value delivered |
|---|---|---|
| "Works on my machine" | Unreviewed, untested against staging data | None |
| "Merged to `main`" | Integrated, not yet deployed | None |
| "Deployed dark" | Code is in prod behind a disabled flag | None yet (safe staging) |
| **"Flag on, monitored, metrics healthy"** | Serving real users with alerts green | **Actually Done** |

## Gotchas
- **Skipping CI on "just a quick prototype":** Prototypes become production systems; wiring lint, typecheck, and secret scanning takes 15 minutes on Day 1 and saves days later.
- **Manual evidence collection:** In regulated environments, generate approval, test, and scan artifacts automatically in CI rather than filling spreadsheets after release.
- **Unwritten rollback plan:** Every PR that touches schema or config should state how to revert it in under 5 minutes.
