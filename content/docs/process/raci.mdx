## TL;DR
**RACI** maps every task to four roles: **R**esponsible (does the work), **A**ccountable (single final owner), **C**onsulted (two-way input before done), and **I**nformed (one-way update after done). Keep **exactly one `A` per row**—especially when humans, AI agents, and CI share a repo.

## Definitions

| Letter | Role | Meaning | Communication |
|---|---|---|---|
| **R** | **Responsible** | Executes the task (can be shared by 1–2 doers or CI) | Active work |
| **A** | **Accountable** | **Exactly one** final decision-maker and approver | Sign-off / owns risk |
| **C** | **Consulted** | Subject-matter input *before* the work is finalized | Two-way (PR comment, review) |
| **I** | **Informed** | Kept up to date *after* a decision or merge | One-way (changelog, report) |

## Worked RACI: Mengty Learns (Owner / Lead / Workers / CI)

This repository splits work across four actors: the **Owner** (human), **Lead Agent** (orchestrator/reviewer), **Worker Agents** (isolated worktrees), and **CI** (`.github/workflows/ci.yml`, `labs.yml`, `quality.yml`).

| Task / Decision | Owner | Lead Agent | Worker Agents | CI |
|---|---|---|---|---|
| **Product scope & priorities** | **A / R** | C | I | — |
| **Wave briefs & worktree setup** | A | **R** | I | — |
| **Writing MDX pages & `<Flow>`s** | C | A | **R** | I |
| **Shared code (`lib/`, `components/`)** | A | **R** | C (`BLOCKERS.md`) | I |
| **Lint, typecheck, test, build, axe** | I | A | C (runs locally) | **R** |
| **Reviewing & merging PRs to `main`** | A | **R** | I | C (required checks) |
| **Secrets, Cloudflare tokens, push `main`** | **A / R** | C | — | — |

Notice two boundaries:
- **Worker Agents never push or merge:** they are `R` in their worktree and log out-of-scope code needs in `BLOCKERS.md` (`C`).
- **CI is `R` for repeatable verification, never `A`:** a passing CI run does not replace human/lead accountability for content accuracy.

## Common mistakes
1. **Two `A`s on one row:** "Shared accountability" means neither person feels responsible when something breaks. Pick one `A`.
2. **Zero `A`s or zero `R`s:** A row with only `C` and `I` never gets done; a row with `A` and no `R` means the owner is doing all the work without knowing it.
3. **Using person names instead of roles:** Naming "Alice" instead of "Team Lead" causes matrix rot every time someone rotates or goes on leave.
4. **Overusing `C`:** Marking 5 people as `C` turns every 20-line PR into a committee. Downgrade non-essential reviewers to `I`.

## Decision rights by domain
Pair your RACI with a quick **decision-rights** table so people know who makes the call without a meeting:

| Decision type | Accountable role | Consulted roles |
|---|---|---|
| **Product priority & customer value** | PO / Business Owner | PM, Team Lead |
| **Technical architecture & ADRs** | Team Lead / Architect | Developers, Ops, Security |
| **Local implementation detail** | Responsible Developer | Peers via PR review |
| **Production release & rollback** | Release Owner / Team Lead | Ops, QA, PM |
| **Active incident response** | Incident Commander (IC) | Ops, Developers, Comms |

## Minimum viable version (1–3 person team + AI agents)
You do not need a spreadsheet for every ticket. Write a **6-row RACI table once** in `AGENTS.md` or `CONTRIBUTING.md` covering:
1. Priorities & scope
2. Feature / content implementation
3. Shared infrastructure / schema changes
4. Automated checks (CI)
5. Merge to `main`
6. Production secrets & deploy

## When it's overkill
- A **solo project with no agents or collaborators**—you are `A` and `R` for everything.
- Creating a new 20-column RACI chart for every sprint or minor bug fix.

## Gotchas
- **Delegating `A` to an AI agent or CI bot:** Automated tools can be `R` (drafting code, running checks), but a human or designated lead must remain `A` for security, production deploys, and factual accuracy.
- **Hidden `C` dependencies:** If a worker needs `lib/home-data.ts` updated before a feature works, mark that dependency explicitly (`BLOCKERS.md`) instead of letting the PR sit stalled.

## Production checklist
- [ ] Every row in the team RACI has **exactly one `A`** and **at least one `R`**.
- [ ] Production secrets, billing, and force-pushes are locked to the human `A`.
- [ ] `C` is reserved for people whose input can actually change the outcome before merge.
- [ ] `I` updates happen asynchronously (PR summaries, changelogs), not in extra meetings.
