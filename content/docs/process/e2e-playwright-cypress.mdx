## TL;DR
A flaky E2E suite trains teams to ignore red builds. Keep suites deterministic with **web-first retrying assertions** (zero `waitForTimeout`), **per-test seeded data**, **reused `storageState`** auth, **stubbed external vendors**, and a **small critical-path PR gate** with Playwright traces uploaded on failure.

## Why it exists
When an E2E suite of 300 tests goes red 20% of the time due to `waitForTimeout(2000)` or shared test accounts, engineers stop trusting it and quarantine failing tests—until a real regression slips straight into production.

## Mental model
Test **real user journeys** against **your** backend and DB, while stubbing external vendors and freezing non-deterministic clocks.

## Do it

```ts
import { test, expect } from '@playwright/test';

test('submits order and shows confirmation', async ({ page }) => {
  // Freeze clock for deterministic date assertions
  await page.clock.install({ time: new Date('2026-11-27T10:00:00Z') });

  // Stub external vendor at network boundary
  await page.route('**/api.shipping-vendor.example/quote', (route) =>
    route.fulfill({ json: { priceCents: 500, etaDays: 2 } }),
  );

  await page.goto('/checkout');
  await page.getByLabel('Order reference').fill(`ORD-${test.info().workerIndex}-${Date.now()}`);
  await page.getByRole('button', { name: 'Place order' }).click();

  // Web-first retrying assertion (never use waitForTimeout)
  await expect(page.getByRole('status')).toHaveText(/order confirmed/i);
});
```

## Gotchas
- **Quarantining without an expiry:** A "temporarily skipped" critical test becomes permanently blind coverage.
- **Uploading traces only on success:** Always set `if: always()` (or `trace: 'on-first-retry'`) in CI so failed runs keep their trace/video artifacts.
- **Asserting on `nth(0)`:** Positional selectors break whenever parallel workers insert rows into the same list.

## Production checklist
- [ ] Ban `waitForTimeout` / `cy.wait(ms)` via ESLint `no-restricted-syntax`.
- [ ] Authenticate once via `storageState` (keep only 1 dedicated login E2E test).
- [ ] Seed test data via API/DB per test with unique run/worker IDs.
- [ ] Run ~5–10 `@critical` journeys in the PR gate and the full suite post-merge.
