## TL;DR
A retrospective is only useful if it changes next week's behavior. Pick a simple prompt (**Start/Stop/Continue**, **4Ls**, or **Sailboat**), review last retro's actions first, and leave with **1–3 owned, tracked changes**—not a wish list.

## 1. Three lightweight formats

| Format | Prompts | Best when |
|---|---|---|
| **Start / Stop / Continue** | What should we **start** doing? **Stop** doing? **Continue** doing? | Default choice; fast and action-oriented (15–30 min) |
| **4Ls** | **Liked**, **Learned**, **Lacked**, **Longed for** | After a major launch or learning wave (surfaces missing tools/knowledge) |
| **Sailboat** | **Wind** (helps), **Anchor** (drags), **Rocks** (risks), **Island** (goal) | Re-aligning on a shared goal and spotting upcoming risks |

## 2. Turning talk into tracked actions
Follow a 4-step agenda so the retro doesn't drift into venting:
1. **Check last retro's actions (3 min):** Did we finish them? If not, drop or re-commit—don't silently carry 10 stale items.
2. **Silent brainstorm (5 min):** Everyone writes notes silently first so quiet voices aren't drowned out.
3. **Dot-vote top 2 themes (5 min):** Discuss *why* the top 2 happened, not every minor annoyance.
4. **Assign 1–3 actions (5 min):** Every action needs **What** + **1 Owner** + **Where it's tracked** (GitHub Issue or backlog card).

## 3. Solo-developer weekly retro (15 minutes, Friday)
Working alone (or with AI agents) still benefits from a 15-minute weekly pause:
```markdown
## Weekly Retro — YYYY-MM-DD
- **Shipped:** (2–3 bullets: what actually reached main/prod?)
- **Friction:** (What wasted > 30 min? e.g., flaky test, unclear prompt, missing script)
- **One change for next week:** (1 concrete fix—e.g., "Add AGENTS.md rule for PowerShell `;`")
```
Notice how updating `AGENTS.md`, templates, or CI scripts turns a solo retro insight into permanent leverage for every future AI agent session.

## Minimum viable version (1–3 person team + AI agents)
- **15–25 minutes every 2 weeks** using **Start / Stop / Continue** in a shared markdown file.
- Cap actions at **2 items max**, both added to the active board so they compete fairly with feature work.

## When it's overkill
- Running a 90-minute facilitated workshop with icebreakers for a **2-person team** that pairs every day.
- Tracking 12 "action items" in a separate Confluence page nobody opens until the next retro.

## Gotchas
- **Zero follow-through:** Nothing kills morale faster than raising the same CI pain 4 retros in a row with no fix.
- **Turning retros into blame sessions:** Focus on *systems, scripts, and clarity*, not who broke the build.
- **Skipping the check-in on old actions:** Always open the retro by marking last week's actions Done or Dropped.

## Production checklist
- [ ] Retro cadence is on the calendar (weekly 15 min solo, or biweekly 25 min for 2–3 people).
- [ ] Last retro's action items are reviewed at the start of every session.
- [ ] Output is capped at **1–3 concrete actions**, each with **one owner** and a **ticket/issue**.
- [ ] Process fixes (CI tweaks, template updates, `AGENTS.md` rules) are committed to the repo.
